Core Classes
LLMClient

Wrapper รอบ LangChain สำหรับ provider เดียว

  • _make_llm() — สร้าง LangChain object ตาม provider (ChatOpenAI, ChatOllama ฯลฯ)
  • chat() — เรียก LLM แบบ invoke ธรรมดา (non-streaming)
  • stream_messages() — stream response ทีละ chunk
LLMManager

จัดการ LLMClient ทุกตัวพร้อมกัน

  • _validate_and_init() — ตรวจ API key ทุก provider ตอน startup
  • get_client(provider) — ดึง client ของ provider ที่ต้องการ
  • available_providers — list provider ที่พร้อมใช้
Shop Layer

ข้อมูลสินค้าดิบ — keyboards 4 รุ่น, mice 3 รุ่น อยู่ใน Python dict ล้วนๆ

list_keyboards() list_mice() @tool

ดึงข้อมูลจาก PRODUCTS แล้ว format เป็น string — โปรแกรมเป็นคนเรียก ไม่ใช่ LLM

SHOP_TOOLS

List รวม tools ทั้งสอง ใช้ตอน bind_tools() กับ LLM

UI Layer (Gradio)

Gradio callback หลัก — รับข้อความจาก user วน tool loop จนได้คำตอบ แล้วอัพเดต UI

update_model_dropdown() update_reasoning_visibility()

Gradio event callbacks — อัพเดต dropdown เมื่อ user เปลี่ยน provider หรือ model

🤔 LLM เรียก Tool เองไหม?

คำตอบ

โปรแกรมนี้เป็นคนเรียก — LLM ไม่ได้ execute tool เอง แค่บอก "ฉันอยากเรียก tool นี้" กลับมาเป็น structured data

สิ่งที่ LLM ส่งกลับมา

response.tool_calls = [
  {
    "name": "list_keyboards",
    "args": {},
    "id": "call_abc123"
  }
]

โปรแกรมเป็นคนรับแล้วเรียกจริงใน chat_fn()

for tc in response.tool_calls:
    if tc["name"] in tool_map:
        result = tool_map[tc["name"]].invoke(tc["args"])  # โปรแกรมเรียก Python function
        current_messages.append(ToolMessage(content=str(result), tool_call_id=tc["id"]))

🔄 Flow การทำงาน

User พิมพ์คำถาม │ ▼ chat_fn() สร้าง llm_with_tools = client._make_llm().bind_tools(SHOP_TOOLS) │ ▼ llm_with_tools.invoke(messages) ← LLM ตัดสินใจว่าต้องเรียก tool ไหม │ ┌───┴──────────────────────────────┐ │ response.tool_calls มีข้อมูล │ response.tool_calls ว่าง ▼ ▼ แสดง "✨ กำลังค้นหาข้อมูล..." แสดงคำตอบ → จบ │ ▼ เรียก list_keyboards() / list_mice() (อ่านจาก PRODUCTS dict → return string) │ ▼ เพิ่ม ToolMessage เข้า messages │ ▼ invoke() อีกครั้ง → LLM ใช้ผลลัพธ์ tool ตอบ
ทำไมต้องมี while True?
เพราะโปรแกรมต้องวน invoke จนกว่า LLM จะตอบเป็น text ธรรมดา (ไม่มี tool_calls อีก) — กุญแจคือ .bind_tools(SHOP_TOOLS) ที่ทำให้ LLM รู้ว่ามี tools ใดบ้าง และตัดสินใจเองว่าจะเรียกหรือตอบตรงๆ
